# LandOps glossary

Use these definitions consistently in code, UI text, and documentation.

| Term | Definition |
| --- | --- |
| API number | The identifier used by the case and public well records to refer to a well |
| authority boundary | The statement that limits what the application is allowed to claim or do |
| case | A bounded review package with submitted clues, evidence, and a jurisdiction |
| conflict | Two or more material claims that do not agree |
| deterministic | Producing the same result from the same input without a live model or external service |
| evidence | A normalized fact linked to a publisher, source record, snapshot, and content hash |
| finding | A structured assertion with a status, confidence, evidence references, and provenance |
| fixture | A fixed test input used to make local behavior repeatable |
| grounding | The evidence and run state that support an answer |
| human review | The point where a person evaluates the packet before a consequential action |
| no match | A source was checked and returned no matching record |
| unknown | A question that the current evidence cannot answer |
| provenance | The record of where a fact or finding came from and which step produced it |
| reported zero | A matching source record explicitly reports zero |
| reconciliation | Comparing submitted clues with independent source records |
| review decision | An append-only approval or revision request for a run |
| run | One execution of the reconciliation workflow |
| snapshot | An immutable captured source response with retrieval metadata and a hash |
| synthesis | A compact review packet that summarizes the run and proposes a route |
